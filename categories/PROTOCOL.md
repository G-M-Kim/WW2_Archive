## 2. 증거와 위키 원고

- 실제 원문을 열어 주장과 해당 부분을 대조한다. 검색 결과 요약·추천 링크를 열람 완료로 표시하지 않는다. 1차 사료(당대 교범·시험/생산/인구통계·작전기록·특허·지도·연설 원영상) 우선, 공신력 있는 기록관·박물관·학술출판물과 전문 연구로 교차검증한다. 1차 자료도 당대 오류·선전·집계 한계를 가질 수 있음을 검토한다.
- 여러 사이트가 같은 원전을 재인용한 경우 독립 출처로 세지 않는다. Wikipedia·팬 위키·검색 요약은 탐색 길잡이로만 사용한다. 접근 불가 원문을 읽은 것처럼 인용하지 않는다. 출처가 적으면 그 한계를 명시한다.
- 기관·저자·자료명·작성/출판일·1차/2차·문서/소장번호·쪽/표/타임코드·URL·열람일·검증한 주장·한계·권리 정보를 SOURCES.json에 기록한다. 저작권 있는 전문/이미지/영상의 대량 복제 대신 자체 한국어 요약과 원문 링크를 쓴다.
- 각 핵심 주장/수치 옆에 출처 ID와 쪽/표/시간을 붙인다. 자료가 지지하는 범위만 쓴다. 개발/계획/주문/시제품/생산/배치/실전, 제식/실측, 이상조건 성능/실전 성능을 구분한다. 사상자·생산량 등의 집계기간과 단위를 명시한다.
- CAT-{국가코드}-SRC-0001, CAT-{국가코드}-RQ-0001을 국가별 장부에서 중복 확인 후 발급한다. 개체 ID는 CAT-{국가코드}-EQP/PER/ORG/GEO-0001 형식으로 필요에 따라 발급한다. 기존 ID는 변경·재사용·삭제하지 않는다. 한 국가의 같은 사람/장비/출처는 여러 카테고리에 걸쳐 재사용한다.
- verified(명시한 주장에 대해 독립 교차검증), source_checked(실제 단일 근거 대조), candidate(탐색 후보), disputed(상충), inaccessible(접근 불가)를 구분한다. 카테고리 방문 완료와 사실 검증 완료는 별개다.
- 주제에 해당하는 실재 자료가 없다는 결론도 검색 범위·근거·접근 한계를 밝혀 기록한다. 자료를 못 찾은 사실을 역사적으로 존재하지 않았다는 증명으로 바꾸지 않는다.

## 3. 항목 특수 기준

- 장비: 형식/개장일/엔진/탄약/고도/하중/시험조건을 고정해 성능을 기술한다. 다른 형식의 최고 수치를 합쳐 가상 장비를 만들지 않는다.
- 인물: '유명'은 전쟁 관련 역할과 문헌상 중요성이다. 찬양/비난만으로 평가하지 말고 실제 행위·책임·사료 한계를 기록한다. 인종·국적의 우월성이나 전쟁범죄 미화를 쓰지 않는다.
- 연설: 보존기관/공식 컬렉션 원영상 URL을 우선 확인한다. 실제 동시대 촬영인지, 연설 전체/발췌/무성 뉴스릴/음성만/정지화면 편집/후대 재연인지 구분한다. 실제 영상이 없으면 음성만을 영상 확보로 세지 않는다. 방송일과 촬영/연설 날짜, 제목 오기·자막 언어·권리·재생 가능 여부를 기록한다.
- 인구·지명·영토: 기준일/공간 경계/명칭 적용기간/실효지배와 법적 지위를 명시한다. 본토·제국·식민지·도미니언·위임통치·점령지·괴뢰정권과 병합 주장을 합산하지 않는다. 지도는 출처·연도·범례·권리 정보를 갖춘 기존 지도 링크를 우선 사용한다.
- 자원: 석유, 강철, 고무, 알루미늄, 크롬, 텅스텐만 본 항목으로 다룬다. 강철 생산과 철광석, 알루미늄 제련과 보크사이트, 원유와 정제/합성유, 천연/합성고무, 국내/식민지/점령지/수입을 분리한다. '자원 없음'을 현대 매장량이나 검색 실패만으로 단정하지 않는다.

## 4. 진도·원자적 저장·검증

1. 선택한 작업의 원고, 국가 SOURCES/QUESTIONS/README, runs/{job_id}.json, QUEUE/STATE/RUN_LOG를 한 커밋으로 갱신한다. 주제 밖 기록이나 공통 파일의 수정은 금지한다.
2. 실제 조사 증분 또는 실질 접근 시도·한계가 문서화된 작업은 reviewed/partial/blocked 중 맞는 상태로 방문 처리한다. 미해결 쟁점에는 질문·연결 ID·근거·완료조건·상태를 남긴다. partial/blocked를 전수 완료로 보고하지 않는다.
3. CAT_VISITED_COUNT를 +1, CAT_NEXT_STEP을 다음 pending 번호(모두 끝나면 null), CAT_LAST_JOB_ID를 이번 작업으로 갱신한다. 남은 과제를 이유로 같은 카테고리를 연속 재방문하지 않는다. 후속 쟁점은 별도 보존한다.
4. GitHub 도구 장애 등으로 원고·진행의 원자적 저장이 실패하면 방문/진도/완료를 주장하지 않는다. 다음 실행은 최신 HEAD를 다시 확인하고 저장되지 않은 해당 작업부터 재시도한다. 이미 저장된 작업은 중복 발급·재커밋하지 않는다.
5. 실행 기록에는 job_id/step/country/category/started_at/completed_at/status/article_path/source_ids/question_ids/research_scope/limitations를 기록한다. RUN_LOG에 같은 job_id를 중복 기록하지 않는다. 미래 commit SHA를 같은 커밋 파일에 지어 쓰지 않는다. 실제 커밋 SHA는 채팅 또는 후속 감사에서 참조한다.
6. python categories/tools/validate.py 를 실행해 작업 순서·상태·원장·파일·참조를 확인한다. 원격 변경 목록이 모두 categories/ 하위인지 검사한다. 이 브랜치에는 별도 연구 CI가 없으며 로컬 검증이 역사적 사실 검증을 대체하지 않는다. 실행하지 못한 검사를 통과했다고 쓰지 않는다.
7. ref 갱신 직전에 HEAD를 재확인하고 expected_sha로 갱신한다. 경합 발생 시 최신 HEAD에 연구 증분을 다시 적용하고 재검증한다. force push·기존 커밋 삭제·무조건 덮어쓰기를 하지 않는다.
8. 모든 133개가 방문되면 CAT_PHASE=first_pass_finished로 바꾸고 미방문/미해결/검증 한계를 집계한다. 예약은 최초 실패 1회와 수동 복구를 별도로 기록하고, 이번 개정 후 남은 COUNT=132로 종료하며 자동 새 순회를 만들지 않는다. 남은 예약 종료까지 실패 때문에 미방문이 남았다면 완료로 가장하지 말고 잔여 항목과 재예약 필요를 보고한다.

## 6. 2026-11-08 예약 재등록과 중복 방지

- 현재 정본 예약은 AUTOMATION.json의 automation_id다. 이전 예약 `Automation_3eee281072dc819194ac5604d3c3b374`는 현재 도구의 전체 조회에 없고 직접 조회도 접근 불가였다. 삭제 또는 중지됐다고 단정하지 않는다. 이전 예약 ID로 실행 중임이 확인되면 연구/커서 변경을 하지 않고 새 예약으로 이관됐음을 짧게 보고하고 종료한다.
- 정기 실행에서는 마지막 저장된 runs 기록의 started_at 이후 2시간이 지나지 않았다면 연구·진도 변경 없이 건너뛴다. 사용자가 직접 요청한 수동 실행은 주기 제한에서 제외한다.
- 시작 시 선택한 job_id를 고정한다. HEAD 경합 뒤 같은 job이 이미 방문됐다면 종료한다. 그 실행에서 다음 job으로 바꾸지 않는다. job이 여전히 pending일 때만 최신 HEAD에 증분을 다시 적용한다. 이 규칙은 이전 예약에서 실행되더라도 적용한다.
- 이 규칙은 연구 원고의 이중 저장과 과도한 진도 전진을 줄이는 절차이며 플랫폼 예약의 취소나 서버 실행 성공을 보장하지 않는다. 현재 등록 확인과 실제 실행 검증을 구분한다.
