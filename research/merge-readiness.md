# 조사 초안 PR 병합 판단 — 2026년 10~11월 연구 검토

**현재 권고: Draft 유지 / PR #1 병합 보류.** 이번 1939년12월27~29일 배치에서 **공식 핀란드 상선 통계의 Wilpas 좌초기록**과 잠수함전 2차자료의 포격·어뢰격침설, **덴마크 Hanne 생존자수(2 vs 25)** 및 **Resercho 기뢰부설일(9/5 vs 11/17)** 등 중대한 사료충돌을 발견해 원문·전몰자명부 대조 과제로 남겼다. 기존의 1939년9월 폴란드 날짜충돌 과제도 여전히 연구백로그에서 추적한다.

사용자가 원하는 승인 흐름은 *조사·자체 사료 검증 → Draft PR → 사용자 검토·명시 승인 → main 병합/공개*이다. 날짜별 사건 후보가 많아졌다고 검증되지 않은 내용을 main으로 편입하지 않는다.

## 단계 구별

1. **연구 스냅샷을 `research/`로 main에 병합:** GitHub Pages 사이트의 `docs/` 페이지에는 직접 게시되지 않지만 **공개 저장소의 main에 누구나 읽을 수 있는 초안**이 남는다. 데이터의 상태·출처·유보표시를 정리한 뒤 명시 승인이 필요하다.
2. **백과사전 본문을 `docs/`에 게시:** 프로젝트의 검증·상충해결·편집 검토 조건을 충족한 사건만 별도 게시용 PR로 이동. 연구색인 전체의 일괄 게시와 다름.
3. **미완료 연구는 `research-backlog.md`에 유지:** 100%의 전쟁사 발굴·역사논쟁 해결을 병합 절대 필요조건으로 요구하지 않는다. 다만 **검증되지 않은 사건을 '확정 사실'처럼 제시하지 않아야 한다**.

## 내가 PR 병합을 권할 시점

- README, 감사 보고서, 연표 각 행에서 **미확인 주장·역사기관 현대 해설·원전 회의록·당사국 선전**을 정확히 구분하고 역사적 오기가 발견된 핵심 기록을 우선 정정.
- 공개 main에 포함될 범위의 출처 URL 접근성, 실제 문서번호·특정 페이지, 중복 별칭·정합성 등을 조사하여 **상태표시가 사실과 충돌하지 않는지** 확인.
- 최소한 **병합 대상의 미등록/링크등록 행은 '미검증'으로 분명히 구별**하고, 샘플 사료 감사를 통해 심각한 오기·잘못된 자료 인용이 없음을 확인. 가능하면 검증된 사건과 미검증 후보 목록을 분리해 **작은 병합 단위**로 만들 것.
- 병합 목적을 분리: **연구 색인의 스냅샷 보관용 병합**은 허가를 받은 후 권고할 수 있지만, **공개 백과사전 본문 출판**은 더 높은 정확도 검증을 요구한다.
- 사용자에게 해당 시점의 사건/출처 수와 남은 위험을 보고하며 **"이제 PR을 병합하는 편이 낫다"라는 추천을 명시적으로 전달**한 뒤 최종 결정을 기다린다.
- 한 번의 응답 또는 GitHub 자동실행만으로 병합·사이트 게시를 자동으로 하지는 않는다.
