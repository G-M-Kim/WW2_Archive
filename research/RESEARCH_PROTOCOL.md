# WW2 Archive — 시간순 역사자료 조사 운영 규칙

## 정본과 재개

- 월별 사건의 정본은 `chronology/YYYY-MM.md`, 범위 밖 사건은 `chronology/prologue.md`와 `chronology/epilogue.md`다.
- 현재 진행 기준은 `WORK_STATE.md`의 단일 `FORWARD_CURSOR`와 append-only `PROGRESS_LEDGER.md`다. 두 값이 다르면 조사 전에 차이를 확인하고 복구한다.
- 출처 정본은 `chronology-sources-v1.md`, 미해결 과제는 `research-backlog.md`다. 새 사건·출처·쟁점은 각 정본에 반영한다.
- `source-audits/YYYY/`는 연도별 사료 감사, `event-drafts/YYYY/`는 상세 사건 초안이다. 이들 문서만 늘리고 월별 연표·출처 등록부·백로그를 갱신하지 않는 작업을 완료로 보고하지 않는다.
- `coverage/chronology/`는 특정 날짜 구간의 범위 검토·후속 대조 자료다. 여기에 기록된 상태는 전체 연표의 완료나 활성 forward 커서를 대체하지 않는다.
- `archive/`는 이전 연표 스냅샷과 과거 운영 이력이다. 과거 날짜·누적 수치·작업 위치는 현재 운영 기준으로 사용하지 않는다.

## 조사 모드

- **forward:** 다음 날짜 구간을 선별 조사한다. 기본 7일, 고밀도 전역은 1~3일, 저밀도 기간은 2~4주로 조정한다. 검증된 사건을 월별 원고에 반영하고 새 출처·미해결 쟁점을 함께 저장한다. 배치가 실제 저장된 뒤에만 종료 다음 날로 커서를 전진한다.
- **backfill:** 과거 누락, 날짜·수치·피해 집계의 이견, 미확인 원자료를 조사한다. forward 커서는 유지한다. 같은 검색을 성과 없이 반복하지 말고 다른 RQ로 이동한다. 연속 두 번의 backfill은 피하고 다음 forward를 우선한다.
- **requested:** 사용자가 지정한 사건·주제·기간을 조사한다. 원장에는 기록하되 자동 forward 커서는 유지한다.
- 사건을 찾지 못한 경우 실제 확인한 범위와 미조사 범위를 구분한다. 근거가 부족한 후보는 확정 사건으로 등록하지 않는다. 미해결은 기존 RQ에 연결하거나 새 RQ로 남긴다.

## 조사 품질

- 당대 정부·군사 문서, 조약·법령 원문, 공식 통계·기록관 자료를 우선한다. 학술 연구와 공신력 있는 기관 전사는 보완·교차검증에 활용한다.
- 검색 결과 요약만 확인한 자료를 원문 열람으로 표시하지 않는다. 출처마다 문서명, URL, 실제 열람 위치(페이지·표·문서번호)와 확인 범위를 기록한다.
- 사건 발생일, 발표일, 서명일, 발효일, 보도일, 현지 시각과 구력·신력을 구분한다.
- 기존 EVT를 먼저 확인하고 중복 생성 대신 기존 행을 보강한다. 날짜 정밀도, 지역·법적 지위를 원자료보다 과도하게 단정하지 않는다.
- 신규 EVT는 월별 정본에 추가한다. 새 출처는 출처 등록부, 미해결 쟁점은 백로그에 반영한다. 사료 감사 문서는 정본 연표의 대체물이 아니다.

## 저장·검증

1. 작업 전 최신 `main`과 사용자가 지정한 활성 작업 브랜치/PR의 HEAD를 확인한다. 과거 브랜치명이나 병합된 PR 번호를 현재 조사 대상으로 가정하지 않는다.
2. 사용자가 지정한 활성 작업 브랜치가 있으면 사용한다. 없다면 최신 main에서 조사 전용 브랜치를 만들고 PR로 제출한다. 기존 활성 PR이 있으면 중복 PR을 만들지 않는다.
3. 월별 원고, 출처 등록부, 백로그, 사료 감사, WORK_STATE, PROGRESS_LEDGER를 한 배치의 원자적 변경으로 저장한다. 원격 HEAD가 바뀌면 최신 내용을 다시 읽고 충돌을 해결한다. 저장 실패 시 커서를 전진시키지 않는다.
4. 날짜·ID·출처 참조·진행 원장을 `python validate_index.py`로 검사한다. 이는 구조 무결성 검사이며 역사적 정확성을 인증하지 않는다. 사이트 검사 시 `python scripts/build_category_pages.py`와 `zensical build --clean`을 실행한다.
5. PR 병합과 Pages 배포는 별도 승인 없이 수행하지 않는다. Actions가 실행 중이면 통과했다고 보고하지 않는다.

## 진행 장부

- `PROGRESS_LEDGER.md`는 append-only다. 기존 행을 덮어쓰거나 삭제하지 않는다.
- forward/recovery는 실제 조사 날짜 범위와 다음 커서를 기록한다. backfill/reconcile/requested는 forward 커서를 유지한다.
- 감사 파일 경로는 저장소 루트 기준 실제 존재하는 상대 경로여야 한다.
- 0/0/0은 실제 근거를 찾지 못했을 때만 허용한다. 두 번 연속 forward 0/0/0이면 허위 성과를 만들지 말고 색인·도구·저장 과정을 진단한다.
- 모든 전역의 미해결 RQ를 끝내야 다음 forward로 넘어가는 것은 아니다. 남은 문제는 백로그에 남기고 정상적인 조사 범위에 따라 전진한다.

## 사용자 보고

한국어 3~5줄로 조사 날짜·모드, 신규/보강 EVT·SRC·RQ, 저장 커밋/PR, CI 결과와 남은 문제, 다음 FORWARD_CURSOR만 보고한다. 상세 증거는 GitHub 원고와 감사 문서에 저장한다.
